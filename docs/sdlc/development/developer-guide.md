<!-- sdlc:auto:start overview -->
TimeTrack Pro V1 is a time and labour management web app generated by the Quorq AI SDLC platform. It is one repository with two applications. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 and Alembic on PostgreSQL 16. It implements email/password sign-in with server-side bearer-token sessions, password reset and set-password emails, System Admin management of users, clients, projects and tasks, clock in and out with breaks, a weekly timesheet of manual hours, editing and deleting time entries, a home dashboard of weekly hours, and a read-only Manager view of direct reports. `frontend/` is a Vite 6 + React 19 single-page app using React Router 7 and Tailwind 4. Its screens are Sign in, Home, Timesheet, Admin Users, Admin Projects, My team and Help, with role-gated navigation. It talks to the API through `src/lib/api.ts`, which uses relative `/api` calls proxied to port 8000 in development, or `VITE_API_BASE_URL` when deployed. The README says the screens run on seeded sample data, but `api.ts` and `auth.tsx` show real API wiring; check individual screens before relying on either claim. Deployment runs from `.github/workflows/deploy.yml`: the backend is built as a Docker image pushed to ECR, and the frontend is published to AWS Amplify.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Python 3.12 (the version used by backend/Dockerfile)
- Node.js with npm (no version is pinned; Vite 6 and React 19 need a current LTS release)
- Docker with Docker Compose, to run PostgreSQL 16 from docker-compose.yml
- Chromium for Playwright end-to-end tests (installed with `npm run test:e2e:install`)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. docker compose up -d db
2. cd backend
3. python -m venv .venv
4. source .venv/bin/activate
5. pip install -r requirements.txt
6. alembic upgrade head
7. python -m app.seed
8. uvicorn app.main:app --reload
9. In a second terminal, from the repository root: cd frontend
10. npm install
11. npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend endpoints live under `/api/<area>`, with one `APIRouter` per feature module in `app/routers/`. Each router is registered in `main.py`.
- Dependencies use `Annotated` aliases: `Db = Annotated[Session, Depends(get_db)]`, `Me` (via `get_current_user`), `Admin` and `Manager` (via `require_role(...)`).
- Role names are exactly 'Employee', 'Manager', 'Payroll Admin' and 'System Admin'. They are enforced by a check constraint and by `require_role`.
- Authentication works like this: `POST /api/auth/login` returns a token. The client stores it in localStorage and sends it as `Authorization: Bearer <token>`. Sessions are stored server-side as a token hash.
- Every POST, PUT, PATCH or DELETE request to `/api` must include an `X-Requested-With` header (CSRF defence). `apiFetch` adds it automatically.
- Validation errors return HTTP 422 with `{"detail": [{"loc": [...], "msg": "..."}]}` and human-readable messages. Conflicts return 409, and access to another user's data returns 403 or 404.
- Timestamps are stored as timestamptz in UTC and returned as ISO-8601 with a `Z` suffix. Local dates are derived from each user's `time_zone`.
- Weeks run Monday to Sunday, and `week_start` must be a Monday in YYYY-MM-DD format.
- Emails are stored lowercase. Client, project and task names are unique case-insensitively, using `lower(name)` unique indexes.
- Schema changes are made only through new numbered Alembic migrations; there is no `create_all` on startup.
- Frontend imports use the `@/` alias for `src/`. All API calls go through `apiFetch` in `src/lib/api.ts`, and styling uses Tailwind with brand CSS variables (`var(--brand-*)`).
- Vitest component tests sit beside their components as `*.test.tsx`; Playwright specs live in `e2e/` as `*.spec.ts`.
- Code quality tools: Ruff for backend lint and format; ESLint plus Prettier for the frontend.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The backend fails to start or connect to the database. | Start Postgres with `docker compose up -d db`. There is no SQLite fallback. The connection comes from `DATABASE_URL` and defaults to the docker-compose service; set `DATABASE_URL` if your database runs elsewhere. |
| `pytest` fails with `ModuleNotFoundError: No module named 'app'`. | Run `pytest` from inside `backend/`, where pytest.ini puts the current directory on the import path. |
| POST, PUT, PATCH or DELETE requests to /api return 403 'You do not have access to this resource.' | Add the `X-Requested-With` header (CSRF middleware), or use `apiFetch`, which adds it. Also check that the Bearer token is valid and the user has the required role. |
| Frontend API calls fail during `npm run dev`. | The Vite proxy forwards /api to http://localhost:8000, so the backend must be running there (`uvicorn app.main:app --reload`). Make sure you have signed in so a session token is stored. |
| The tables or test data you expect are missing. | Run `alembic upgrade head`, then `python -m app.seed`, from backend/. |
| /docs, /redoc or /openapi.json return 404. | These are disabled when the environment setting is 'production'. Run with a non-production environment locally. |
| Playwright cannot start the backend web server. | The config runs `.venv/bin/alembic` and `.venv/bin/python` from backend/. Create `backend/.venv`, install requirements.txt into it, and make sure Postgres is running. Alternatively, set `E2E_BASE_URL` to an already-running app. |
| `npm run build` passes but the deployment or `npm run typecheck` fails on type errors. | The build does not typecheck. Run `npm run typecheck` and fix the reported errors, which are often an untyped `useState({})` that is later read for named fields. |
| The deploy workflow passes values named `VITE_API_SECRET_KEY` and `NEXT_PUBLIC_API_SECRET_KEY` as plain text into the frontend build. | Anything with the `VITE_` prefix is inlined into the public bundle, so it cannot stay secret. Remove the value from deploy.yml or move it to GitHub Secrets, and do not rely on it for authorization. |
<!-- sdlc:auto:end troubleshooting -->
