<!-- sdlc:auto:start overview -->
TimeTrack Pro V1 is an early-stage scaffold for a time and labour management web app (timesheets, approvals, leave, labour rules, reports). It was generated by the Quorq AI SDLC platform and lives in one repository with two applications. `frontend/` is a Vite + React 19 + TypeScript single-page app styled with Tailwind CSS v4 and routed with react-router-dom v7. Its approved screens are Sign In, Home, Timesheet, Admin Users, Admin Projects and Help, and they still render seeded sample data. They are not wired to the API yet, but `src/lib/api.ts` provides the `apiFetch` seam for doing that. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 and Pydantic 2. Its only real route is `GET /health`, and there are no models yet. It uses SQLite (`./app.db`) by default, and setting `DATABASE_URL` points it at PostgreSQL 16, which `docker-compose.yml` provides. Pushes to `main` trigger a GitHub Actions workflow that pushes the API image to AWS ECR and publishes the frontend to AWS Amplify.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js with npm (for the Vite 6 / React 19 frontend)
- Python 3.12 (the version used by backend/Dockerfile) with pip
- Docker with Docker Compose (optional: for the PostgreSQL 16 service or for building the API image)
- Playwright Chromium browser (optional: for end-to-end tests; installed with `npm run test:e2e:install`)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. cd frontend && npm install
2. cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt   # Playwright's e2e config expects the backend packages in backend/.venv
3. (Optional) Start PostgreSQL from the repo root: docker compose up -d db. Then set DATABASE_URL so the backend uses it instead of the default sqlite:///./app.db.
4. cd backend && .venv/bin/python -m uvicorn app.main:app --reload   # API on http://localhost:8000; tables are created from the models on startup
5. cd frontend && npm run dev   # Vite dev server on http://localhost:5173, which is the backend's default allowed CORS origin
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend imports use the `@/` alias for `frontend/src`, configured in vite.config.ts and tsconfig.json.
- Each approved screen is one default-exported module in `src/screens/`. Routes are declared in `App.tsx`: app pages render inside `AppShellLayout` (a sidebar plus `<Outlet/>`), while `/sign-in` sits outside the shell.
- Styling uses Tailwind CSS v4 plus brand CSS variables (`--brand-*`) defined in `index.css` and `lib/brand.ts`.
- API calls should go through `apiFetch` in `src/lib/api.ts`. It reads `VITE_API_BASE_URL`, falling back to http://localhost:8000. For the bearer token it prefers a session token stored in localStorage and otherwise uses `VITE_API_SECRET_KEY`.
- TypeScript strict mode is on, but `noImplicitAny` and `strictNullChecks` are off.
- Component tests sit beside the components as `*.test.tsx` under `src/`. Playwright specs live in `e2e/` and are excluded from Vitest.
- On the backend, there is one router per architecture component in `app/routers/`. Unimplemented routes return the typed `StubResponse` instead of raising.
- Backend configuration comes from environment variables: `DATABASE_URL` (default `sqlite:///./app.db`) and `ALLOWED_ORIGINS` (comma-separated; defaults to the localhost:5173 Vite origins).
- Database requests use one session per request via the `get_db` dependency. Tables are created with `Base.metadata.create_all` at startup, and there are no migrations yet.
- Lint and format with ESLint and Prettier on the frontend and Ruff on the backend. The platform gates on `npm run lint`.

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The screens show sample data and changes don't reach the API. | This is expected: the generated screens use seeded data. Wire a screen to the backend by calling `apiFetch` from `src/lib/api.ts`. Note that the backend currently exposes only GET /health. |
| The browser blocks API calls with a CORS error. | The backend only allows http://localhost:5173 and http://127.0.0.1:5173 by default. Run the frontend with `npm run dev` on that port, or set `ALLOWED_ORIGINS` (comma-separated) to your frontend origin. |
| `npm run build` succeeds but `npm run typecheck` fails. | The build does not typecheck. Fix the reported errors, which are often an untyped `useState({})` read for named fields, before relying on the code. |
| `npm run test:e2e` fails to start the backend web server. | Playwright runs `.venv/bin/python -m uvicorn` from backend/. Create backend/.venv and install requirements.txt into it first, and install Chromium with `npm run test:e2e:install`. |
| Chromium crashes while running e2e tests in a container. | The config already passes `--disable-dev-shm-usage`. If crashes persist, increase the container's /dev/shm size. |
| `pytest` cannot `import app`. | Run pytest from inside `backend/` so pytest.ini (with `pythonpath = .`) is picked up. |
| Model changes don't appear in an existing database. | There are no migrations, and `create_all` only creates missing tables. During development, delete `backend/app.db` (SQLite) or reset the Postgres volume. Adopt Alembic before the database holds data worth keeping. |
| The backend fails at startup when DATABASE_URL points at Postgres. | Make sure the database is up (`docker compose up -d db`) and the URL matches its credentials (user, password and database are all `app`, on port 5432). The psycopg v3 driver is installed. |
| Security: deploy.yml hardcodes the API shared secret in plain text (`VITE_API_SECRET_KEY` / `NEXT_PUBLIC_API_SECRET_KEY`). | That value is committed to the repo and inlined into the public frontend bundle, so treat it as exposed. Rotate it, move it to a GitHub Actions secret, and avoid relying on a client-side shared secret for authentication. |
