<!-- sdlc:auto:start overview -->
TimeTrack Pro V1 is a time and labour management web app (roles: Employee, Manager, Payroll Admin, System Admin) generated by the Quorq AI SDLC platform. It is one repository with two applications. frontend/ is a Vite 6 + React 19 + TypeScript single-page app that uses react-router-dom 7 and Tailwind CSS 4. It is served locally on Vite's dev server, which proxies /api to the backend. backend/ is a FastAPI 0.115 service using SQLAlchemy 2, Alembic migrations and PostgreSQL 16 (via psycopg). The backend currently implements a /health probe, cookie-based session auth (login, logout, me, password reset) and System Admin user administration (list, create, edit, deactivate). The root README still says the backend has only a health check; the code shows more. The other screens (Home, Timesheet, AdminProjects, Help) exist in the frontend, but no backend endpoints for timesheets, projects, leave or reports exist yet. Deployment runs through GitHub Actions on push to main: the backend Docker image goes to AWS ECR and the frontend bundle goes to AWS Amplify.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Python 3.12 (the backend Dockerfile uses python:3.12-slim)
- Node.js with npm (no version is pinned in frontend/package.json)
- Docker with Docker Compose, to run PostgreSQL 16 from docker-compose.yml
- PostgreSQL 16 reachable via DATABASE_URL; there is no SQLite fallback
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. docker compose up -d db
2. cd backend
3. python -m venv .venv && source .venv/bin/activate
4. pip install -r requirements.txt
5. alembic upgrade head
6. python -m app.seed
7. uvicorn app.main:app --reload
8. In a second terminal: cd frontend
9. npm install
10. npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend routers live in backend/app/routers/, one module per area, each with an /api/<area> prefix (/api/auth, /api/admin/users). /health is unprefixed.
- State-changing /api requests (POST/PUT/PATCH/DELETE) must send an X-Requested-With header or they get a 403. frontend/src/lib/api.ts apiFetch adds it automatically.
- Auth is a server-side session in an HttpOnly, SameSite=Strict cookie. The SPA never stores tokens and calls the API through apiFetch with same-origin credentials.
- Database schema changes go only through Alembic migrations in backend/migrations/versions/ (numbered NNNN_description.py). The app does not create tables at startup.
- Emails are stored lowercase, and uniqueness is enforced by a unique index.
- FastAPI dependencies use Annotated aliases (e.g. Db, Admin). Role checks use require_role(...) on the backend and the AdminOnly wrapper on the frontend.
- Validation errors are normalized into {detail: [{loc, msg}]} with user-facing messages.
- OpenAPI docs (/docs, /redoc, /openapi.json) are disabled when the environment setting is production.
- Frontend imports use the @/ alias for src/. Styling uses Tailwind with brand tokens exposed as CSS variables (var(--brand-*)).
- Vitest component tests sit beside their components as *.test.tsx. Playwright specs live in frontend/e2e/ as *.spec.ts.
- Code style is enforced with ESLint and Prettier (frontend) and Ruff (backend).
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The backend fails to connect to the database on startup or in migrations. | Start Postgres with `docker compose up -d db` and make sure DATABASE_URL points at it. The default targets the docker-compose service. There is no SQLite fallback. See backend/app/config.py and .env.example. |
| pytest raises ModuleNotFoundError: No module named 'app'. | Run pytest from inside backend/, so pytest.ini's pythonpath=. applies. |
| POST/PATCH calls to /api return 403 'You do not have access to this resource.' | Send the X-Requested-With header. Use apiFetch from frontend/src/lib/api.ts, or add the header in curl or other clients. |
| The login succeeds but the session cookie isn't kept when running locally over http. | The cookie is marked Secure unless the environment setting is local, dev or development. Set the environment accordingly for local work (see backend/app/config.py). |
| /docs returns 404. | API docs are disabled when the environment setting is production. Use a non-production environment locally. |
| `npm run test:e2e` times out waiting for http://127.0.0.1:8000/health. | The Playwright config expects a virtualenv at backend/.venv with requirements installed, and a reachable Postgres via DATABASE_URL. Alternatively, set E2E_BASE_URL to a running app. |
| Playwright reports that the browser is not installed. | Run `npm run test:e2e:install` in frontend/. |
| `npm run build` succeeds but `npm run typecheck` fails. | This is expected: the build does not typecheck, and generated screens may not satisfy tsc. Fix the type errors before relying on typecheck in CI. |
| Frontend API calls from a deployed build go to localhost. | Set VITE_API_BASE_URL at build time. If it is unset, calls are relative and rely on the Vite /api proxy, which exists only in dev. |
| deploy.yml hardcodes VITE_API_SECRET_KEY and NEXT_PUBLIC_API_SECRET_KEY values in the frontend build env. | Values passed to the frontend build are inlined into the public bundle, so they cannot be secret. Treat them as exposed and remove or rotate them if they are meant to be secret. The code shown here does not read them. |
| The root README says the backend has only a health check. | That text is out of date. The backend also serves the /api/auth/* and /api/admin/users* endpoints. |
