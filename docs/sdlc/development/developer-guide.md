<!-- sdlc:auto:start overview -->
TimeTrack Pro V1 is a time and labour management web app (roles: Employee, Manager, Payroll Admin, System Admin). It is generated by the Quorq AI SDLC platform as two applications in one repository. `frontend/` is a Vite 6 + React 19 + TypeScript SPA using React Router 7 and Tailwind CSS 4. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2, Alembic migrations and PostgreSQL 16 (psycopg 3); there is no SQLite fallback. The backend implements: a `/health` probe; bearer-token session auth (login, logout, me, password reset request/confirm) under `/api/auth`; and System Admin user management (list, create with a set-password email, update, deactivate) under `/api/admin/users`. The frontend has screens for sign-in, home, timesheet, admin users, admin projects and help, behind an auth-aware shell. The frontend README says the screens still run on seeded sample data. The root README's claim that the backend has only a health check is out of date. Deployment runs via a GitHub Actions workflow: the backend image is pushed to ECR and the frontend is published to AWS Amplify.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Python 3.12 (the version used by backend/Dockerfile) with pip and venv
- Node.js with npm (no version is pinned in frontend/package.json)
- Docker with Docker Compose, to run the PostgreSQL 16 service in docker-compose.yml
- Chromium for Playwright, installed via `npm run test:e2e:install` (only needed for end-to-end tests)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. docker compose up -d db
2. cd backend
3. python -m venv .venv
4. source .venv/bin/activate
5. pip install -r requirements.txt
6. (Optional) export DATABASE_URL=<your Postgres URL>. backend/app/database.py reads DATABASE_URL via settings and defaults to the docker-compose Postgres service.
7. alembic upgrade head
8. python -m app.seed
9. uvicorn app.main:app --reload
10. In a second terminal: cd frontend
11. npm install
12. npm run dev  # Vite proxies /api to http://localhost:8000
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend has one APIRouter per area, with an `/api/...` prefix and tags. Request/response Pydantic models live in the router module. schemas.py holds only a StubResponse placeholder.
- Dependencies are injected with typing.Annotated aliases (e.g. `Db`, `Admin = Depends(require_role("System Admin"))`).
- Schema changes happen only through Alembic migrations. The app does not create tables on startup.
- Emails are lowercased before storage and lookup. Uniqueness is enforced by a unique index and returns 409 on conflict.
- Auth uses opaque bearer tokens stored server-side as hashes in the `sessions` table. The frontend keeps the token in localStorage and sends `Authorization: Bearer`.
- CSRF defence: any POST/PUT/PATCH/DELETE to /api must send an `X-Requested-With` header, or it gets a 403. apiFetch in src/lib/api.ts adds it automatically.
- Validation errors are normalized to 422 responses of the form `{detail: [{loc, msg}]}` with user-friendly messages.
- OpenAPI docs (/docs, /redoc, /openapi.json) are disabled when the environment setting is 'production'.
- The frontend imports through the `@/` alias, which maps to src/. All HTTP calls go through `apiFetch`, which throws `ApiError`. The API base URL comes from VITE_API_BASE_URL; when unset, paths stay relative and use the Vite proxy.
- Admin-only routes are wrapped in `AdminOnly` (role 'System Admin'). Unauthenticated users are redirected to /sign-in.
- Styling uses Tailwind 4 plus brand CSS variables (`var(--brand-*)`) defined in index.css and brand.ts.
- Unit tests sit beside components as *.test.tsx (Vitest + Testing Library, jsdom). Playwright specs live in e2e/*.spec.ts.
- TypeScript runs in strict mode but with noImplicitAny and strictNullChecks disabled.
- Ruff (backend) and ESLint + Prettier (frontend) are the lint and format tools.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| POST/PATCH requests to /api return 403 'You do not have access to this resource.' | Send the `X-Requested-With` header on state-changing requests. Use `apiFetch` from src/lib/api.ts, which sets it. |
| Backend fails to connect to the database or migrations error out | Start Postgres with `docker compose up -d db` and confirm DATABASE_URL points at it. There is no SQLite fallback. |
| `pytest` fails with ModuleNotFoundError: app | Run pytest from the backend/ directory so pytest.ini's `pythonpath = .` applies. |
| Playwright cannot start the backend web server | Create the virtualenv at backend/.venv and install requirements.txt into it, and make sure Postgres is reachable. Alternatively, set E2E_BASE_URL to run against an already-running app. |
| `npm run build` succeeds but `npm run typecheck` reports errors | Expected per the frontend README: the build does not typecheck. Fix the type errors (often untyped `useState({})`) before relying on tsc. |
| /docs returns 404 | Docs are disabled when the environment setting is 'production'. Run with a non-production environment locally. |
| Deployed frontend calls localhost instead of the API | VITE_API_BASE_URL must be set at build time, because Vite inlines it into the bundle. |
| deploy.yml hardcodes values for VITE_API_SECRET_KEY and NEXT_PUBLIC_API_SECRET_KEY in plaintext | Treat these values as exposed. They are committed to the repo, and VITE_-prefixed variables are inlined into the public bundle. src/lib/api.ts does not reference either one. Rotate the value if it guards anything, move it to a secret store, and remove it from the workflow if it is unused. |
